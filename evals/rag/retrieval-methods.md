# 分块与混合检索的研究依据

本页记录方法依据与适用边界；实测结果、采用决定与复跑入口统一见 [RAG 评测](README.md)。技术栈保持 Chroma、现有 embedding 接口和本地词法检索。

## 论文依据与实现边界

| 一手来源 | 可用于本项目的结论 | 不应混淆的边界 |
| --- | --- | --- |
| Hearst, 1997, [TextTiling](https://aclanthology.org/J97-1003.pdf)，§3–4 | 词汇连贯度的低谷可以作为连续子主题边界；值得与固定字符分块比较。 | Markdown 标题、句界约束或自行设计的动态规划切分，只能称结构感知或受其启发，不能称完整复现 TextTiling。 |
| Qu et al., NAACL Findings 2025, [Is Semantic Chunking Worth the Computational Cost?](https://aclanthology.org/2025.naacl-findings.114.pdf)，§2、实验 | 相邻句向量距离断点和聚类是可测候选；语义分块的收益并不一致，必须计入额外编码成本。 | 论文的英语任务结果不能直接外推到这里的小型中文支持知识库；不能因为方法复杂就选它。 |
| Chen et al., 2023, [Dense X Retrieval](https://arxiv.org/html/2312.06648v2)，§4.3–4.4 | 细粒度单元可用于定位父段：先多取候选，再映射原段、按最大相似度去重；不同粒度比较需要相同上下文预算。 | 原文 proposition 是模型生成、消解指代且自足的原子事实。句子切分、邻段扩展或标题前缀都不是 propositionizer。 |
| Cormack et al., SIGIR 2009, [Reciprocal Rank Fusion](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)，§1 | `Σ 1/(k+rank)` 避免直接比较不同评分尺度；论文用预实验固定 `k=60`。 | 60 是其数据上的选择，不是小语料上的最优保证；缺失候选与排名截断会改变融合。 |
| Bruch et al., [An Analysis of Fusion Functions for Hybrid Retrieval](https://arxiv.org/html/2210.11934)，§3.1、§4–5 | 测试归一化凸组合 `α·dense+(1−α)·BM25`；论文发现 CC 在所测任务优于 RRF，RRF 对参数敏感。 | 论文对两路候选并集补算缺失通道分数后归一化。把未召回通道填 0 不是等价实现；超参数只可在开发集选。 |
| Lù, 2024, [BM25S](https://arxiv.org/html/2407.03618v1)，§2 | 在建索引时预计算词项贡献并稀疏存储，查询时只累加命中词项；可减少重复建索引和全库评分成本。 | 复用 `rank_bm25` 索引是工程优化，并非 BM25S 实现；论文吞吐倍数不能借作本项目实测。 |
| Günther et al., [Late Chunking](https://arxiv.org/html/2409.04701v3)，§3 | 先对长文本产生上下文化 token 向量，再按片段边界 pooling，保留片段外上下文。 | 当前接口仅返回每条输入的最终向量，没有 token embeddings；对句向量分组、求平均或加标题均不是 late chunking，本轮不伪实现。 |

## 五类可测候选

保留旧的 512 字、64 字重叠、dense/本地回退及 RRF 作为对照。先固定融合比较分块，再固定分块比较融合；最后验证组合，避免把所有改变归因于单一方法。下面参数是实验建议，不是采用值。

| 候选 | 主要变量 | 预期收益与代价 |
| --- | --- | --- |
| 结构约束分块 | 保留标题/段落/列表，完整句子装箱；目标约 256/512 字、有限整句重叠 | 减少句子和列表被切断；无需额外模型调用。标题重复与碎片数量需要计量。 |
| 词汇连贯度分块 | 相邻句窗口的词项相似度，低谷断点，最小/最大长度约束 | 无 embedding 边界调用；可能捕获主题转换，也可能对中文同义改写不敏感。 |
| 语义断点分块 | 同一真实 embedding 模型，连续句余弦距离分位点，标题和长度约束 | 有机会改善主题边界；额外句子向量和短片段会增加入库成本。 |
| 小单元定位、大上下文返回 | 句子/短段索引，命中后映射同一父段或有界邻域，去重后预算截断 | 区分“定位粒度”和“阅读粒度”；需要防止同源命中挤占 Top-k，扩展不得跨来源或吞掉关键证据。 |
| 校准混合融合 | 上述胜出的分块上比较 dense、BM25、RRF（例如 10/60）、CC（例如 α=0.25/0.5/0.75），候选深度一致 | CC 保留分数间距；RRF 不需要分数归一化。候选深度和权重必须一起记录，不能只报告最终 Top-k。 |

分块并不一定都要在产品中保留。复杂候选没有质量收益时，删掉在线实现和切换开关，仅保留可复现的离线实验入口、论文依据和结果。重排会额外改变模型、推理次数和延迟；只有候选召回充分而前列排序仍明显失效时，才值得单列对照，不能与分块收益合并。

## 公平比较与效率测量

- 使用相同语料快照、真实 embedding 服务及模型标识、查询、Top-k 和总上下文字符或 token 预算。短片段可能增加命中位置数，大段可能靠返回更多正文提高命中，必须同时报告证据覆盖与上下文长度。
- 标注应锚定原文来源与必要证据，不绑定旧 chunk ID；重复/重叠文本不重复增加命中。报告 Hit@k、完整证据命中、分证据 Recall、MRR、安全相关遗漏和无答案题表现；检索命中不等同于回答改善。
- CC 用同一候选并集上的真实两路分数。Chroma 当前 `1/(1+distance)` 是变换分数，不能当原始 cosine；若使用向量重算，应复用同一查询向量并记录全库精确检索与 Chroma 近似检索的区别。零方差通道不提供排序信息，不应制造区分度。
- BM25 缓存或预计算必须有入库、替换、删除后的失效规则，并验证与未缓存排序一致。不能通过省略索引一致性检查而掩盖过期索引。
- 分别计量建索引时间、真实 embedding 调用次数/文本量、索引大小、冷启动、暖查询 p50/p95。远程查询向量耗时与本地检索耗时分开，端到端另外实测；缓存真实向量的离线排名实验不能冒充在线端到端延迟。
- 小语料应先验证真实瓶颈。仅为测复杂度构造的重复/扩展语料可用于性能压力实验，必须标明合成身份，不能计入模型召回质量证据。

## 数据划分与选优规则

`closing-40.jsonl` 及已有逐题报告已经被项目使用，继续使用时属于已知的小样本回归。按每主题前两题/后两题分开发与验证只提供固定分区；由于主题、证据和历史结果已可见，不能称独立未见测试。同一证据的改写、同一来源模板及近重复问题应同组，尽量按证据组或主题做分组交叉验证，防止同义题泄漏。

先冻结候选和选择准则，再只用开发区选择。建议先要求安全关键漏检不恶化，再比较完整证据召回与 MRR；质量相同取计算成本更低、代码更少者。验证区用于一次验证和报告，不在看过结果后继续选择参数；若据其修改方法，应将它转为开发数据并承认需要新的测试证据。小样本差值同时给出逐题变化和分组重采样区间，不夸大统计确定性。

项目所有者已复核的证据、工程编写的新问题、真实模型向量、实际用户数据必须分别说明。对未人工复核的新题，不能继承旧审核记录。最终结论只能是“给定语料、模型、预算及候选集合中的较优方案”，不能声称普遍最优或已完成临床/产品验收。
