# 次日反馈任务生命周期与挂起检查点

## 背景

ADR-0014 已让次日反馈的计划编号、待填槽位和已填值跨轮及跨运行时恢复，但任务只有激活与无任务两种实际状态。重复开始会重置进度并重复发送 24 小时行动计划卡片；普通聊天虽然继续原支持链路，任务却仍保持激活，导致后续改善状态可能被误提交。

需要补齐同一反馈任务的重复开始、取消、挂起与明确恢复，同时保持每轮事件初始化、安全升级和无记忆会话边界，不引入通用任务框架。

## 决策

- 次日反馈任务区分为无任务、激活和挂起三种生命周期状态；激活沿用现有 `checkin` 值，挂起使用现有任务字段的 `suspended` 值，无任务继续使用空值。
- 同一激活任务重复开始时只回复当前待填步骤，不重置计划编号、槽位或已填值，也不产生新的行动计划事件。
- 明确取消激活或挂起任务时，清除任务、待填槽位和已填值；不删除或修改原 24 小时行动计划及历史消息。
- 激活任务收到普通文本时将任务挂起，并继续既有消息分流、安全风险评估、知识检索和文本回复链路。挂起任务不消费改善状态，只有明确恢复表达才重新激活。
- 恢复时保留原计划与待填槽位，只提示当前缺失步骤；每轮行动计划事件仍完整初始化，不恢复或重放旧事件。
- 沿用 ADR-0014 已有跨轮白名单，不新增检查点字段。任务字段的新取值与其他业务状态一样只含可序列化原生类型，并按会话线程隔离。
- 高风险文本继续进入既有安全升级；待审核会话在图运行前拒绝新消息，取消和恢复表达不得绕过该限制。
- 对话提交继续复用与 HTTP 表单共用的次日反馈应用入口，不新增数据库表、公开接口、SSE 事件类型或通用任务暂停栈。

## 后果

重复开始不再丢失反馈进度，普通插话不会造成意外提交，挂起任务可在运行时重建后明确恢复。不同会话和无记忆会话分别保持既有隔离与隐私语义。

该决策只扩展 ADR-0014 已持久化任务字段的生命周期取值，保留 ADR-0002 的可序列化检查点、ADR-0005 的条件边路由和 ADR-0012 的每轮临时状态初始化。挂起只是本次对话业务状态，不等同于人工审核的图中断。

## 验收

公开 `/api/chat/stream` 测试覆盖重复开始、激活与挂起取消、普通插话、明确恢复、未选计划恢复、文件检查点跨运行时恢复、会话隔离、无记忆及高风险审核；完整 Docker 测试要求零跳过。
