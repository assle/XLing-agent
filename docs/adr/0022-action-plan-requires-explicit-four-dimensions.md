# 行动计划保持四维完整触发并修正边界测试预期

## 背景

独立端到端用例“考驾照让我很紧张，晚上睡不着，我一直刷视频不去背题”原先被预期为直接生成 24 小时行动计划，但文本只明确提供触发事件、身体反应和行为，没有明确表达想法。把“紧张”自动转换为某种认知内容，会替用户补充未表达的信息；现有系统继续追问与 ADR-0007 的四维完整触发约定一致，失败来自测试预期而非行动计划生成故障。

## 决策

- 保持认知行为四维追问的触发条件不变：触发事件、想法、身体反应和行为全部具有用户明确表达的信息后，才生成 24 小时行动计划。
- 不从紧张、害怕等情绪词自动推断具体想法，也不为了让单条消息测试通过而放宽完整性要求。信息不足时继续自然追问缺失维度。
- 将 `ind-e2e-action-plan-02` 修正为边界用例：期待继续追问且不产生 `action_plan` 事件；`ind-e2e-action-plan-01` 保留为四维完整后生成计划的正向用例。
- 后续四维完整的测试输入必须明确包含想法，不依赖评测编写者或模型替用户推断。

## 后果

系统可能需要多一轮追问才能生成计划，但不会把未表达的认知强加给用户，也不会仅因存在困扰就自动生成行动安排。独立端到端结果需要在修正测试预期后重新运行，原结果保留为已暴露评测口径问题的历史记录，不通过修改代码迎合错误标签。

## 验收

- 四维缺少想法时继续追问且不生成计划。
- 四维全部明确覆盖时生成计划，并保持现有计划复用和后续反馈行为不变。
- 修正后的独立测试同时覆盖四维完整与信息不足两条路径。
