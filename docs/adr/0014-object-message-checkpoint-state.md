# 对象消息的确定性入口与跨轮状态白名单

## 背景

24 小时行动计划卡片需要把用户选择送回现有对话，并在缺少计划编号时继续同一次次日反馈。对象点击是已确定的业务输入，不应经过模型分类、知识检索或模型回复；同时，计划编号和改善状态需要在下一轮及运行时重建后继续可用。

ADR-0012 要求每轮完整初始化状态，以避免回复、检索结果和业务事件残留。若恢复整份旧状态会重放事件，若每轮全部丢弃又无法完成跨轮补槽，因此需要明确区分本轮输入与跨轮业务状态。

## 决策

- 聊天请求的消息字段兼容原字符串与 `action_plan` 对象。对象编号必须重新按当前用户和当前会话读取服务端计划，客户端标题与展示属性不作为业务事实。
- LangGraph 在现有安全检查、长期记忆、消息分流、知识检索和回复准备之前进入对象确定性分支。只实现补次日反馈计划槽位、无任务时保存聚焦对象、其他支持流程中保留原进度三种路径，不建立通用对象注册表或流程引擎。
- 每轮完整初始化消息类型、当前对象、回复、检索结果、行动计划事件、审核决定和诊断等临时字段。
- 仅从既有检查点恢复 `focused_object`、`checkin_task`、`checkin_slots`、`checkin_values` 白名单字段。其值只含可序列化原生类型，并按会话线程隔离；不保存数据库模型或会话。
- 次日反馈启动与对象补槽共用同一组任务状态。反馈保存及首次提交安全升级由 HTTP 表单和对话共用的应用入口执行，重复提交继续更新原记录且不重复升级。
- 对象结果复用现有行动计划、文本 token、等待审核、错误和完成事件；用户历史保存可读的计划选择描述，而不是原始对象 JSON。

## 后果

对象点击获得确定性、低延迟行为，文件检查点可跨运行时恢复次日反馈进度，同时不会重发上一轮回复、检索结果或行动计划事件。无记忆会话不会因此读取或新增长期记忆；本次对话所需的对象状态仍按检查点保留。

该决策仅窄化补充 ADR-0012 的每轮初始化边界，保留 ADR-0002 的可序列化检查点、ADR-0005 的条件边路由及既有人工审核暂停规则。
