# 消息分流按当前目的处理资源查询并取消通用任务词硬短路

## 背景

当前消息分流在模型判断前使用通用任务词直接判为 CHAT。“项目失败后我一直很消沉”因包含“项目”且未命中有限的心理支持关键词，被提前送入日常对话并跳过安全风险评估。另一方面，仅询问心理中心电话、预约或值班信息的独立测试被标为 CONSULT，导致事实资源查询被要求进入认知行为四维追问，消息目的与后续处理路径不一致。

## 决策

- 用户只询问心理中心或部署机构的电话、预约方式、值班人员、办公室位置等事实信息时，按 CHAT 中的部署资源查询处理：直接检索部署方提供的适用资源，不启动认知行为四维追问；资料不足时明确说明不知道，不编造电话、人员、地点、开放时间或服务可用性。
- 同一消息同时包含心理困扰或危险信号时，仍按 CONSULT 或 RISK 的既有规则处理，资源查询措辞不得压过安全风险评估；高风险继续优先安全升级，低、中风险继续遵循安全风险评估先于知识检索的顺序。
- 取消 GENERAL_TASK_WORDS 命中后直接判为 CHAT 的硬短路。除保留明确高风险直连外，由消息分流模型结合完整句子判断当前目的；心理支持与通用任务关键词只作为模型不可用时的备用依据，不再提前绕过模型。
- 不为独立测试中的具体句子写死风险等级。持续消沉、兴趣下降等表达先正确进入心理支持路径，再由安全风险评估给出 LOW、MEDIUM 或 HIGH，人工标签用于验收而不是生成专用规则。

## 后果

事实资源查询可以直接得到信息或明确的未知说明，多义任务词与心理困扰同时出现时不再被单个名词提前分流。取消硬短路会增加普通任务消息对分流模型的调用及相应延迟；模型不可用时仍需要测试备用路径，不能把关键词备用结果描述为完整语境理解。本决策不新增公开意图类型，资源查询是 CHAT 路径内的处理分支。

## 验收

- “项目失败后我一直很消沉，以前喜欢的事也不想做了”不再因“项目”直接判为 CHAT，并进入安全风险评估。
- 纯资源电话、预约、值班人员和位置查询走 CHAT＋部署资源查询，不产生认知行为四维追问事件，知识不足时不编造。
- 资源查询与心理困扰或明确危险同时出现时，心理支持和安全升级优先。
- 普通编程、学习和通用事务仍正确判为 CHAT；分流模型不可用时验证备用路径不导致异常或伪造资源信息。
