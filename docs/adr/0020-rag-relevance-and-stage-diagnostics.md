# RAG 区分目标来源召回与回答相关性并按阶段定位漏损

## 背景

独立 RAG 测试以单一 `expectedSources` 判定命中，6 个未命中集中在两份通用支持文档；但部分结果中的其他文档同样包含足以回答问题的内容。单一来源指标因此混合了“指定知识没有召回”和“检索结果无法支持回答”两种不同问题。若直接换模型、增加重排或调参，又无法区分查询改写、dense、BM25 与融合排序各自造成的漏损。

## 决策

- 检索评测同时保留两套指标：**目标来源召回**衡量原先指定文档是否进入 Top K，用于诊断知识覆盖和召回漏损；**回答相关性命中**衡量 Top K 是否存在任何足以支持回答的片段，用于衡量结果的实际可用性。
- 原始目标来源及其历史结果保持不变。新增可接受的相关来源必须逐题人工确认并记录理由，不能由检索器或回答模型为自身输出补标；目标来源漏检不得因另一来源相关而从诊断指标中删除。
- 对确认的内容漏检，先保存并比较原查询、各改写查询、dense 排名、BM25 排名及融合前后排名，区分“候选阶段未召回”和“召回后被融合或截断挤出”。只修改证据指向的最小环节，不预设更换 Embedding、启用 HyDE、增加重排或调整 RRF 参数。
- 任何检索修改除冻结回归集和当前独立集外，还必须用未参与规则、提示词或参数调整的新查询复验，避免对已知错题过拟合。

## 后果

目标来源召回与回答相关性分别计算，报告可以表达“指定文档未命中但回答依据已召回”等中间状态。新增人工相关性标注会增加评测成本；新旧指标含义不同，比较前先对齐口径。分阶段诊断会增加一次实验的记录量，并提供候选召回、融合和最终返回的定位依据。

## 验收

- 每题分别报告目标来源召回、回答相关性命中及人工标注依据。
- 漏检案例能够定位到查询改写、dense、BM25、融合或 Top K 截断中的具体阶段。
- 检索策略变更同时提供原回归、独立测试及新查询复验结果，并明确各集合是否参与过修改。
