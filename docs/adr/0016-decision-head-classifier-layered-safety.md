# 单次前向决策头分类器与分层安全策略

## 背景

消息分类主路径此前只有生成式分类器（Qwen2.5-0.5B + LoRA，GGUF/Ollama）一种模型形态：逐 token 生成一个标签词，置信度固定为 0.8，无法表达"高风险灰区"与"类别间分歧"。2026-10-30 的决策头实验（`finetune/reports/decision-head-20261030/summary.md`）在同一基座、数据与超参下证明：固定标签线性决策头单次前向即可输出四类概率，固定 160 例回归集上 160/160、高风险误报 0，本机 P50 约 34 ms；但该回归集已曝光且为合成数据，不能直接外推为真实泛化。

需要把决策头接入业务评估路径，并利用概率输出建立不确定性处理机制，同时保留既有安全语义：明确高风险关键词直连、失败不解释为低风险、生成式分类器继续可用。

## 决策

- 新增 `classifier_backend` 配置：`decision_head`（默认）与 `ollama`（原生成式路径，保留为回退复核）。决策头在应用进程内懒加载共享实例（基座 + LoRA 适配器 + 决策头 + 温度校准，全部只读本地文件），同步单次前向，异步入口经 `asyncio.to_thread` 调用；自定义决策头不进入 GGUF/Ollama。权重缺失或加载失败时自动回退生成式主路径；测试经 `tests/conftest.py` 固定为 `ollama`，不加载真实权重。默认回退模型与输入契约同步对齐为当前已选的 `xling-general-cls-05b:quoted-f16` / `quoted`。
- 概率先经温度校准（`finetune/scripts/fit_decision_head_temperature.py` 在 training-only 验证集 128 条上拟合，T≈1.94，复用 `app.services.risk_calibration.TemperatureScaler`），所有阈值作用在校准后概率上。
- 分层安全策略按以下顺序执行：
  1. 明确高风险关键词直连高风险（不变，决策头与复核均不调用）。
  2. `P(高风险) ≥ 0.5` 直接判高风险。
  3. `P(高风险) ∈ [0.15, 0.5)` 为灰区，或最大类别概率 `< 0.70`，或前两名概率差 `< 0.30`：回退生成式分类器复核。复核一致采用该标签；复核分歧按规则严重度就高（高风险 > 低落 > 焦虑 > 正常），置信度降权。
  4. 复核不可用或标签无效：灰区样本按保守高风险处理（置信度 0.4），其余沿用保守中风险评估；决策头自身加载或推理失败时退回原生成式主路径。
- 阈值（0.5 / 0.15 / 0.70 / 0.30）为工程初始值，全部配置化，待新鲜盲测集校准；评估结果的置信度改用校准概率，`model_version` 记录决策头与温度版本，每次分层决策写入 `assessment.decision_head` 诊断事件（标签、概率、margin、是否回退、原因）。
- 业务关键词策略、风险轨迹、安全升级与保守回退（焦虑/中风险/0.3）保持不变；不新增数据库表、公开接口或 SSE 事件类型。

## 后果

消息分流获得逐例概率与不确定性处理能力：边界样本不再被当作确定标签，灰区与低置信样本由生成式复核兜底，复核失败时按保守方向处理。决策头推理不再依赖 Ollama 在线，但权重为本机实验产物，部署环境需自行准备 HF 权重与 torch/transformers/peft 依赖。

该决策不改变 ADR-0010 的安全优先顺序；决策头只替换分类模型形态与置信度来源，不构成诊断，也不替代人工审核。固定回归集满分与延迟数据仅为当次描述，生产替换资格仍需新鲜盲测集独立验证与人类标签复核。

## 验收

`tests/test_decision_head_assessment.py` 覆盖高置信直判、高风险达阈值直判、灰区复核一致与分歧就高、低置信回退、复核故障与无效标签的保守处理、决策头故障退回生成式、关键词直连跳过模型、异步对应路径；原 `test_classifier_assessment.py` 等回归保持通过。真实模型端到端验证确认高置信直判与"灰区 + 复核不可用 → 保守高风险"行为符合预期。
